# D3: широкий экран без полос (DM_D3_WIDE)

Телефон 20:9 (2400x1080), игра выводит 16:9 (окно NVN 1600x900 в режиме приставки, кадр 1280x720 в портативном). Цель —
как XC2 (заметки порта Xenoblade 2, не опубликованы): игра сама рендерит в пропорциях экрана (2000x900 / 1600x720), обзор Hor+
(вертикальный FOV тот же, по бокам видно больше), UI не растянут.

Все адреса — `main` апдейта 2.7.7, build id `2607a74f5df7754cc0357b5df7e496931355d8ca`, смещения от базы модуля (= смещения
в `work/exefs-update/main.raw`; в этих местах `work/patched/main.patched.bin` совпадает с оригиналом). Проверено дизассемблером
(capstone); карта «слот GOT → функция NVN» построена по загрузчику процедур `0xe2…` (`adrp/add x1,"nvnXxx"; blr x19` →
`ldr x8,[GOT]; str x0,[x8]`). Исходники движка — `X/Client/Gfx/NX64/NX64NVNCore.cpp` (строка по `0xe60e1d`).

## Как D3 выбирает разрешение

Системный размер дисплея игра не спрашивает (из `oe::`/`vi::` только OperationMode/PerformanceMode/OpenDefaultDisplay/
CreateLayer/GetNativeWindow). Всё задаётся константами в одном месте.

| Что | Где | Как |
|---|---|---|
| Инициализация NVN-ядра | `0xe7830` (вызов из `0x29a12c`, открытие окна Gfx) | глобал `G` = `[GOT 0x114c970]` → `0x179bc58` |
| Размеры/аспект | `0xe7858 mov x8,#0x640` · `0xe785c mov x9,#0x500` · `0xe7860 movk x8,#0x384,lsl#32` · `0xe7864 movk x9,#0x2d0,lsl#32` · `0xe7868 mov w10,#0x8e39` · `0xe786c movk w10,#0x3fe3,lsl#16` · `0xe7870 str w10,[x22,#0x10]` · `0xe7874 stp x8,x9,[x22]` | `G+0x00` = 1600x900 (приставка), `G+0x08` = 1280x720 (портатив), `G+0x10` = 1.7777778f (16/9) |

| Окно NVN (3 swap-текстуры) | `0xe6940` | текстуры `G+0x68/+0xe0/+0x158` размером `G+0x00` (всегда 1600x900), `nvnWindowBuilderSetTextures(3)`, `SetPresentInterval(G+0x14)`, `nvnWindowInitialize(G+0x32d0)` |

| GetAspect | `0x29a7f0` | `ldr s0,[gfx,#0x258]` |

### Аспект 3D-камеры

- `0x266740` (вызывается из `0x3de94`/`0x430b4` сразу после `GetAspect`): вьюпорт через `0x3d8a0`, затем `str s0,[cam,#0x48]`
  (аспект камеры) и `0x265070` → `0x264a40` → `0x29b7a0`.
- `0x29b7a0` — перспективная матрица: `m11 = 1/tan(fov/2)` (`bl tanf` `0x29b7d0`, fov ×0.5), `m00 = m11/aspect` (`0x29b7e8 fdiv s2,s0,s10`).
  FOV вертикальный ⇒ шире аспект = **Hor+**.
- Глобал `0x10a5ad0` (аспект, нач. 4/3) пишется в `0x32c408`: `Letterbox ? 16/9 : GetAspect()`; читается `0x32cf80`
  («аспект поменялся?» → перезагрузка UI).

### Единственная константа 16:9 — Letterbox

`0x29b480`: `gfx` флаг бит 5 (опция `Letterbox`, строка в таблице префов `0x27d1b4`) **и** `|16/9 − аспект| > 0.01` → 1.
Тогда `0x3d800/0x3d8a0` берут 16/9 и сужают вьюпорт только по вертикали (для экранов уже 16:9); для широкого экрана
вьюпорт остаётся во всю ширину ⇒ 3D было бы растянуто. Литерал 16/9 `0xeb0b10` используют только эта проверка и её
вызыватели (`0x3d84c…`, `0x14fc0c`, `0x32c400`, `0x3a1ac8`). `1600.0f/900.0f` в коде — посторонние пороги (`0x8489f0`,
`0x94b860`, `0x3f1a48`, `0x7049c8`, `0x7ab140`); прочие `mov #1600/#900` — не размеры экрана.

### UI

Виртуальное пространство UI — **960x720 (4:3)**: `0x34ba70` умножает нормированные координаты на `960.0f` (`0xeb09e0`) и
`720.0f` (`0xeb0e68`). Прямоугольник UI строит `0x34baf0`: вьюпорт (`0x3d800`) × реальный размер окна (`0x12f030` →
`[+0x20]` vtable `+0x28`), и если аспект ≠ 4/3 (`0x34bb58`: `|aspect − 4/3| > 0.01`) — по центру берётся 4:3-полоса
шириной `высота × 4/3` (`0xeb085c`), `x0 = (w − h·4/3)/2`. Это логика ПК-версии (где D3 поддерживает любые пропорции,
включая 21:9): центр — 4:3, элементы с привязкой к краям вылезают за 960 и встают к краям реального экрана. При 16:9 полоса
4:3 = 1200x900 со сдвигом 200; при 2000x900 — та же 1200x900 со сдвигом 400. Ожидание: UI **не растянут**, центральные
окна/меню по центру, HUD (глобусы, панель навыков, мини-карта) у краёв экрана. Ничего патчить не нужно.

## Что делает DM_D3_WIDE (по умолчанию выкл.)

`dm/host/hle_d3.c` `dm_d3_wide_install()`, вызов из `dm/host/main.c` `host_preload` сразу после `load_modules`
(до первой гостевой инструкции; размер экрана уже известен — `nativeSurface` идёт раньше `nativeStart`).

- Проверка сборки: 10 слов `0xe7850…0xe7874` и 4 слова `0x29b480…` побайтно; не совпало — ничего не меняется, лог `【红】[wide]`.
- Патч в памяти (mprotect RW → запись → RX, сброс i-cache), NSO и `patch_nso.py` не трогаются:
  - `0xe7858 mov x8,#W`, `0xe785c mov x9,#Wh` (высоты 900/720 в `movk` остаются),
  - `0xe7868/0xe786c mov/movk w10` = биты float `W/900` (аспект `G+0x10`),
  - `0x29b480 mov w0,wzr; ret` — проверка Letterbox всегда «нет» (при 16:9 она и так возвращает 0).
- `DM_D3_WIDE=1` → `W = front_game_res(1)` (900 × аспект экрана, 2400x1080 → 2000), `DM_D3_WIDE=<ширина>` — явно (1601…3200);
  `W` кратно 16, `Wh = W·4/5` кратно 16 (2000 → 1600). Не задан / `0` / экран не шире 16:9 — как было.
  Лог: `[wide] main+0xe7858 window 1600x900 -> 2000x900, handheld 1280x720 -> 1600x720, aspect 2.2222 …`.
- Для экранов, где `W·4/5` не делится на 16 ровно, аспект портативного режима отличается от `W/900` < 0.5 % (одно поле аспекта на оба режима).
- Хост не менялся: swap-текстуры W×900, кроп W×900 (или Wh×720), `present_native` ставит геометрию буфера = кроп, композитор
  масштабирует в SurfaceView во весь экран — без искажения.

## Шестерёнка

`DmActivity.showD3Settings` «Формат картинки»: `16:9 с полосами` / `растянуть` / **`Широкий экран (со следующего запуска)`**
(pref `aspect` = 2). `applyDoomSettings` ставит `DM_D3_WIDE=1` при запуске; `applyAspectLayout`: игра, запущенная широкой,
— SurfaceView во весь экран; выбрано «широкий», но игра запущена без него — 16:9 с полосами до перезапуска.

## Проверка на телефоне

1. Шестерёнка → «Широкий экран» → перезапуск. В логе `[wide] main+0xe7858 … 2000x900`, `[nvn] WindowCrop 0,0 2000x900`,
   `Present at the game's output size 2000x900`.
2. 3D: круглые объекты круглые, по бокам больше мира; герой по центру.
3. UI: меню/инвентарь/диалоги по центру не растянуты; HUD у краёв; тексты не обрезаны; ролики; загрузочные экраны (фоны
   могут быть 16:9 с полями — так и на ПК).
4. Портатив (`handheld`): кроп 1600x720.
5. Если 3D растянуто — значит аспект не дошёл до камеры (проверить `gfx+0x258` / путь `0xea0e0`); если UI прижат к левому краю
   или растянут — смотреть `0x34baf0` (размер окна для UI) и `0x12f030`.

## Экраны загрузки во весь экран (DM_D3_WIDE_STRETCH_LOADING, 02.11.2026)

Пожелание автора: в широком режиме картинка загрузки (арт акта с подсказками) не 16:9 с полосами, а растянута на весь экран.
Сделано на хосте обрезкой кадра при выводе, раскладку игры не трогаем.

### Что такое экран загрузки D3 (статика, capstone по `work/exefs-update/main.raw`)

**Это не UI-контрол.** В `.ui` есть `BattleNetLoadingScreen_main` (Act1…Act4 × `4x3` / `EndCapLeft` / `EndCapRight`, LoadingText, Logo), но
картинку рисует отдельный код напрямую, а не дерево UI (текстуры Act5 вообще есть только в main, не в `.ui`):

| Что | Где | Суть |
|---|---|---|
| Кадр экрана загрузки | `0x3ebc0` | зовут главный цикл `0x40810` (`0x41418`: если `[x28]\|[x28+0x10]`, иначе `0x41430 bl 0x3dbd0` = конец загрузки; `0x408dc` при `(*st & 0x1004) == 4`) и блокирующие загрузки (`0x3d37c`, `0x3d510`) |
| Состояние | `st = *(*(g+0x10) + 0x800)`, `g` = main+0x1905610 (GOT 0x114a840) | `st+0x6c` = **экран загрузки поднят** (ставит `0x3ecf8` на первом кадре, снимает только `0x3dbd0` в `0x3dc9c`); `st+0x70` = режим = глобал `0x1767bc4` на старте: **0 = арт** (`0x32e200` грузит текстуры, `0x3ee18 b 0x32ec60` рисует), иначе — просто заливка окна (`0x3ed8c…0x3edc8`, растягивать нечего) |
| Загрузка текстур | `0x32e200` | структура `[0x185e8a8]`: `+0x08` 4x3, `+0x10` EndCapLeft, `+0x18` EndCapRight, `+0x20` логотип, `+0x28` значок загрузки, `+0x38/+0x40` анимация точек / текст `LoadScreenText` (подсказка); акт по `0x4caf30`/`0xd9bb0` (0 / 100 / 200 / 300 / 400 = Act1…5) |
| Отрисовка арта | `0x32ec60` | в UI-единицах (960×720): EndCapLeft **x −160.2…0** (`0x32ecac` mov/movk = `0xc3203334`, только если полноэкранный прямоугольник `0x3d9e0` начинается левее 0), центр 4x3 **0…960**, EndCapRight **960…1120.2** (`0x32ed74` = `0x448c0666`, если экран правее 960), y 0…720; логотип 0…960, точки загрузки x≈401…440 y≈654…690, текст — внутри 4:3 |
| UI → пиксели | `0x34bf50` | `px = ox + ui·sx`, `py = ui·sy`, `{sx, sy, ox}` в main+0x1862680 (= 4:3-полоса окна, `0x34baf0`) |

Итого арт = **−160.2…1120.2 × 0…720 = 1280.4×720 = 16:9** (центр 4:3 + «уши» по 160 единиц). При 16:9 он ровно во всё окно; при
2000×900 (sx 1.25, ox 400) — px 199.75…1800.25, т. е. 200…1800, по 200 px чёрного с каждой стороны; в портативе 1600×720 (sx 1, ox 320) —
160…1440. Всё остальное на экране загрузки (логотип, подсказка, точки) внутри этой полосы.

`ActSplashDialogBackgroundScreen` («АКТ I» при входе в акт) — UI-диалог только с текстом (`ActSplash.ui`: заголовок/подзаголовок и
кнопка во весь экран, без текстур) поверх мира; `acttransitions_dialog_main` — тоже текст. Их не трогаем: под ними 3D-мир, растягивать его нельзя.

### Что делает хост

* `dm/host/hle_d3.c` `ls_install` (из `dm_d3_wide_install`, только если окно реально расширено): сверка слов `0x3ebe0` (цепочка
  `g → +0x10 → +0x800`, `ldr w8,[x21,#0x6c]`), `0x3ecf4` (`str 1 → +0x6c`), `0x3ed84` (`ldr w9,[x21,#0x70]; cbz`), `0x3ee18`
  (`b 0x32ec60`), `0x32ecac`/`0x32ed74` (константы −160.2 / 1120.2), `0x34bf50` (`adrp/add 0x1862680; ldp sx, sy`), GOT 0x114a840;
  не совпало — красная строка, выкл. Затем регистрирует `g_nvn_present_crop`.
* `dm/gfx/nvn/hle_nvn.c` `nvnQueuePresentTexture`: после копирования кропа окна в задание вывода зовёт `g_nvn_present_crop(j.crop)`
  (поток игры, в момент её present — состояние читается ровно для этого кадра, не по опросу пада).
* `ls_present_crop`: 4 чтения (`g+0x10`, `+0x800`, `st+0x6c/+0x70`, `{sx,sy,ox}`; куча гостя / образ main напрямую, плохой указатель =
  «нет»). Если `st+0x6c && !st+0x70`: `l = ceil(ox − 160.2·sx)`, `r = floor(ox + 1120.2·sx)`, `b = round(720·sy)`, обрезка по кропу игры;
  если полоса уже всё окно — ничего. Иначе кроп = `crop.x + l, crop.y, r − l, b` (2000×900 → **200,0 1600×900**; портатив → 160,0 1280×720).
* Дальше без изменений: `vulkan_present.cpp` (`present_native`) ставит буферу окна размер кропа (`ANativeWindow_setBuffersGeometry`,
  пересоздание swapchain на входе/выходе из загрузки), композитор масштабирует буфер в SurfaceView во весь экран — непропорционально,
  как в режиме «растянуть» (16:9 → 20:9, +11 % по ширине).
* Ограничения: при маркере `gfx-present-native = 0` (и на Mac/HarmonyOS) вывод сохраняет пропорции кропа → будет 16:9 с полосами, как
  раньше. Если игра выводит кадр не в том же потоке/кадре, что рисует (сдвиг на кадр), на границе загрузки возможен один кадр не того вида.

### Переключатель

* `DM_D3_WIDE_STRETCH_LOADING` — по умолчанию **1** при включённом `DM_D3_WIDE`; `0` — выкл. (полосы как раньше). Без широкого режима не действует.
* Шестерёнка: флажок «Широкий экран: растягивать экраны загрузки на весь экран (со следующего запуска)» под «Формат картинки»
  (pref `d3_stretch_loading`, по умолчанию вкл.; `applyDoomSettings` ставит env; `dm/env` сильнее).

### Проверка на телефоне

1. Широкий экран, перезапуск. В логе после `[wide] main+0xe7858 …`: `[wide] loading screens: the 16:9 act art (main 0x32ec60 …) is presented
   alone and stretched …`. Красная строка `[wide] main+0x… differs` = не та сборка.
2. Вход в игру / телепорт / смена акта: `[wide] loading screen (st 0x… +0x6c 1 +0x70 0): art UI -160.2..1120.2 -> px 199.75..1800.25 x
   0..900.0 (sx 1.2500 ox 400.0): present crop below, stretched to the screen`, `[wide] loading screen: present 200,0 1600x900 of the window
   crop 0,0 2000x900, stretched to the screen`, в logcat `dm-vulkan`: `Present at the game's output size 1600x900`. Картинка загрузки — во весь
   экран без полос (растянута на ~11 % по ширине), подсказка и точки видны.
3. Конец загрузки: `[wide] loading screen over: present the whole window 0,0 2000x900 again`, `Present at the game's output size 2000x900`;
   мир Hor+, не растянут. Первый кадр мира не должен быть растянут (если мелькает — сдвиг present на кадр, см. ограничения).
4. Если загрузка с `+0x70 ≠ 0` (заливка без арта) — строк нет, ничего не меняется.
5. `DM_D3_WIDE_STRETCH_LOADING=0` в `dm/env` → строка `…=0: loading screens keep their 16:9 art with side bars`, полосы как раньше.
